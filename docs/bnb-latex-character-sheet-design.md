# bnb-latex D&D 3.5e Character Sheet Design

This document defines the print-layout direction for D&D 3.5e sheets generated by `bnb-latex`.

## Context and user workflow

- Canonical state lives in BeefBrain YAML.
- Sheets are printed from that YAML.
- During play, users update values with pencil on paper.
- After play, updates are reconciled back into YAML.

Design must optimize for **fast at-table reference** while preserving enough detail for **quick recomputation** when conditions change.

## Core display model: final first, components adjacent

For any calculated value shown on sheet (skills, saves, AC, attacks, etc.):

1. Show the **final total** as the primary visual value.
2. Show the **component breakdown** immediately adjacent (same row or a compact secondary line).

Example:

`Jump +7`  
`Str +2, Ranks +6, Feat +2, ACP -3`

## Numeric formatting rules

1. Always show explicit sign for modifiers (`+7`, `-3`).
2. Use consistent abbreviations (`Str`, `Dex`, `Ranks`, `Feat`, `ACP`, `Misc`).
3. Keep semantic sources (what contributes) rather than only arithmetic totals.
4. Use deterministic source ordering.

Recommended component order:

1. Ability contribution (`Str`, `Dex`, `Con`, `Int`, `Wis`, `Cha`)
2. Training/ranks
3. Feat/class/racial sources
4. Equipment/armor/load effects
5. Circumstance/temporary/misc effects

## Skill section policy

Skills are high-frequency play data and should follow strict layout rules:

1. Skill name in left column.
2. Final value in right-aligned numeric column with strong emphasis.
3. Compact component line below or beside the value.

Nested rank source policy:

- Default view: show `Ranks +N`.
- **Detailed variant only:** include class-by-class rank breakdown (e.g. `Ranks +8 (Ranger 7, Fighter 1)`).

## Variant expectations

### `dnd35-streamlined`
- Prioritize fast scanning and dense tables.
- Keep component lines short and abbreviated.
- Exclude tertiary details unless required for clarity.

### `dnd35-detailed`
- Include fuller decomposition and secondary references.
- Include rank-source parentheticals where available.

### `dnd35-spellcaster`
- Keep same final+component grammar as other variants.
- Allocate extra space to casting-critical metrics (DC contributors, concentration-adjacent values, caster-level context).

## Density and legibility standards

1. Keep page 1 focused on highest-frequency gameplay data.
2. Use tabular numeric alignment for fast comparison.
3. Preserve pencil-writing room in mutable fields.
4. Never compress below practical print legibility.

Compression ladder (in order):

1. Abbreviate labels.
2. Tighten spacing/punctuation.
3. Move detail to secondary micro-line.
4. Split onto continuation area/page before over-compressing text.

## Print ergonomics

- Reserve writable space for frequently changing values (HP damage/temp, conditions, temporary bonuses/penalties).
- Ensure grayscale readability; do not depend on color.
- Use line weight that survives consumer printing and photocopying.

## Data and template implementation guidance

1. Use `bnb-core` calculated outputs as canonical totals and source components.
2. Preserve unknown component keys; render them with safe fallback labels.
3. Keep output deterministic (stable sorting, stable formatting, stable escaping).
4. Build shared formatter/macros for repeated “final + components” rows to avoid drift across templates.

## Out of scope for this document

- Full visual art direction.
- New gameplay rules/calculation logic in `bnb-core`.
- Browser-side PDF compilation behavior (covered elsewhere).
